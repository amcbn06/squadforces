Submission types by platform

Codeforces

Contest and standalone problem submissions are tracked with full solve-type detail.

Badge Description
✓ Live Solved during active (live) contest participation.
✓ Virtual Solved during a virtual contest replay.
▲ Upsolving Solved after the contest ended (upsolved from the contest page).
✓ Standalone Solved as a standalone problem (practice, not tied to a contest run).
WA / TLE … Wrong verdict — best wrong submission (WA, TLE, RE, etc.), problem not solved.
+N Number of wrong submissions before first accepted.

The Upsolving stats section below the matrix aggregates these counts per user across all CF contests in an assignment.

AtCoder

AtCoder results are shown as a simple accepted / not-accepted indicator.

Badge Description
✓ Accepted — the problem has been solved.
✗ Not accepted — attempted but not solved, or no submission found.
· No data — not synced yet or user has no AtCoder handle set.

Solve-type breakdown (live / upsolving) is not tracked for AtCoder due to API limitations.

Kilonova

Kilonova problems use a 0–100 scoring system (or a custom max for some problems). Scores are displayed with a red → yellow → green color gradient.

Display Description
100 Standalone problem — raw score (full score = green).
250/500 Contest — accumulated score / total possible score across all contest problems.
0 Zero score (no accepted submission or all wrong).
— No data — not synced yet or user has no Kilonova handle set.

In contest sub-rows, each cell shows the raw score for that individual problem. A score equal to the problem's maximum counts as solved.

CSES and Codeforces EDU — marked by hand

CSES has no API, and Codeforces does not publish submissions for its EDU practice problems, so the app cannot check who solved these. Members tick problems off themselves instead.

Display Description
✓ Marked as solved. This is self-reported, not verified against the site.
○ Not marked yet. Click it to mark the problem as solved; click the ✓ to undo. You can change your own row; an admin can change anyone's.
· Not marked (someone else's cell, read-only).

The title of these problems can't be looked up either. Enter it in the optional Title field when adding the problem, or set it later with the ✎ button on its row (the person who added it, or an admin). Without one, the row shows the task number.
